# Monica for Extension

Monica 的 Chrome/Edge 与 Firefox 桌面浏览器插件，采用独立的 Manifest V3 构建。管理界面复用并独立维护 Monica WebUI 源码，运行时不依赖 Monica Server WebUI。

## 当前状态

当前正式版本为 **1.0.104**，Chrome/Edge 使用 `dist/`，Firefox 153+ 使用 `dist-firefox/`。Windows Firefox 155.0.1 已完成隔离测试；本地 Firefox 包未签名，临时加载、永久安装的签名要求和 OneDrive 回调配置见 [Firefox 说明](docs/FIREFOX.md)。本版改动见 [1.0.104 发行说明](docs/releases/Monica-Extension-1.0.104.md)，后续改动记录在[下一版发行说明](docs/RELEASE-NEXT.md)，`0.1.48` preview-beta 的已发布记录保留在[历史说明](docs/releases/Monica-Extension-0.1.48.md)。问题可通过 [Bug 报告](https://github.com/Monica-Pass/Monica-for-Extension/issues/new?template=bug.yml) 提交。

- Popup 只接收登录项摘要；点击后由后台将选中项目的必要字段发送到匹配页面。
- 普通登录项可单独开启“允许免解锁填写”；锁定时仍可点击填写已标记账号的用户名和密码，其他保险库功能仍受解锁保护。
- Popup 可发现主页面及跨域 iframe 登录表单、选择填充目标，并填充用户名、密码和当前 TOTP。
- 登录提交、SPA 按钮和密码变更会显示隔离的保存/更新弹窗；候选密码只在后台内存保留 60 秒。
- Popup 可显式填充证件、账单地址、银行卡和支付账号；通用 `number`/`code` 字段不会被猜测。
- 旧明文原型数据会在首次创建加密密码库时迁移并删除。
- WebDAV Basic Auth、连接测试、手动同步和多连接管理。
- 兼容 Android 的普通 `.zip` 与 `MONICA_ENC_V1` 加密 `.enc.zip`。
- 登录、TOTP、银行卡、证件、地址、支付账号、笔记及 Passkey 元数据导入。
- 浏览器修改和删除会写入新的 Android 快照，未知文件和未来 JSON 字段原样保留。
- 基于远端文件、ETag 和项目 revision 的三方冲突检测；冲突时停止覆盖。
- Bitwarden US、EU 和标准路径自托管服务登录，支持 PBKDF2、Argon2id、身份验证器/邮箱/YubiKey 代码 2FA 和 Token 刷新。
- Bitwarden 个人及组织共享的登录、TOTP、银行卡、身份与安全笔记 Cipher 导入；个人 Cipher 可创建，个人和有权限的组织 Cipher 可更新、删除。
- 支持浏览器本地、MDBX2、KeePass 和 Bitwarden 中可导出的 ES256 Passkey；需要身份验证的网站可在独立 Monica 窗口验证主密码。本地／文件库使用零签名计数；Bitwarden 按官方规则保持 0，历史非零计数先同步、递增并确认服务器写入后再签名。使用统计保存在本机。
- Bitwarden revision 冲突检测和异常空密码库防误删保护。
- 默认自动同步：Bitwarden 使用官方 SignalR 通知和单条 Cipher 增量读取；WebDAV 页面可见时每 15 秒检查，MDBX2 沿用 Rust 增量分段，KDBX 与 Android 快照通过 ETag 跳过未变化文件。
- 手机修改上传到共同服务器后，已打开的列表、详情和 Popup 自动刷新。本机保存会安排上传；编辑中的草稿保留，保存前校验版本，避免覆盖其他设备的新内容。
- 外部源修改进入加密 mutation queue；管理页显示待同步、失败次数和显式重试入口。
- 本地写操作串行提交，IndexedDB 只有在事务完成后才报告成功，避免并发保存相互覆盖。

当前版本的登录填充、密码保存/更新、身份与支付填充、WebDAV、Bitwarden 和 Passkey 主流程均有真实 Chromium MV3 E2E 覆盖。

支持 **简体中文、English、日本語、한국어、Deutsch、Español、Русский、Tiếng Việt** 共 8 种语言，与 Android 版的语种保持一致。语言切换仅位于“设置与备份 → 界面语言”，也可选择“跟随浏览器”；创建页、解锁页、Popup 与网页提示自动沿用同一偏好。语言包离线提供，Manifest 名称、说明和工具栏文案同步覆盖。字段识别与界面语言独立；切换语言不会修改账号名称、密码或 Android 数据。详见 [本地化支持范围](docs/LOCALIZATION.md)。

0.1.27 在相同 Chromium、2,000 条合成登录项和 100 条验证码数据下，登录列表的保留 V8 堆由 59.74 MiB 降至 8.08 MiB，Popup 由 14.07 MiB 降至 5.79 MiB。它们是请求垃圾回收后测得的页面 JavaScript 堆，不代表浏览器总内存；主密码派生仍使用 64 MiB Argon2id。测量范围与复现方式见 [性能说明](docs/PERFORMANCE.md)。

## 日常使用

1. 点击插件图标，按需解锁 Monica。
2. 登录页选择匹配账号，填充用户名、密码和 TOTP；跨域 iframe 可在“填充目标”中切换。
3. 提交新密码后，在页面右上角选择保存源并确认保存或更新。
4. 地址、证件或结账页面从 Popup 选择对应项目；银行卡安全码只在这次显式点击后发送。
5. 网站请求创建或使用 Passkey 时，在页面确认弹窗中核对网站、账户和保存目标，再继续或取消。随后默认还要在 Monica 独立窗口验证身份：主密码模式输入主密码，设备密钥模式使用已配置的 Windows Hello；只有网站明确表示不要求用户验证时才会跳过这一步。
6. 在“设置与备份”中定期下载加密整库备份；恢复后使用备份创建时的主密码。

### 浏览和编辑密码库

管理页直接打开“全部项目”。可以从侧栏进入登录项、钱包、笔记、验证码等类型；API 密钥通过密码项目的新建类型管理，原生 API Token 记录仍可在“全部项目”中查看和编辑；“筛选”支持按数据库、Android 分类、收藏和项目类型组合浏览，归档与回收站保留独立入口。

登录项和全部项目共用紧凑列表，各密码项目直接平铺，不再按网站、标题或手动设置堆叠。项目内已有的多组账号和密码仍在详情中管理。

“新建”先选择内容类型。密码、Wi-Fi、SSH 和条码保留 Android 的记录格式；SSO 是密码记录中的“登录方式”，用于记录通过 Google、Apple 等第三方账号登录的网站。表单先显示常用字段，两步验证、网络高级设置、自定义字段等按需展开，保存按钮固定在底部。页面、弹窗和展开操作采用短时过渡，系统开启减少动态效果时自动关闭。

语言选择位于“设置与备份”的首张卡片，创建／解锁页和 Popup 仍可直接切换语言。旧版概览的加密偏好保留在备份兼容层中，不改变或删除原有条目，也不再写入 Android 首页配置。

### API 密钥与 Android 同步

API 密钥独立保存服务商、令牌、可选 API 地址、备注、自定义字段及收藏。密钥与受保护字段默认隐藏，不进入列表摘要、搜索索引或网站自动填充。

本地库可直接使用；当前开发构建已内置 MDBX 引擎，可直接新建或导入数据库并配置 WebDAV。已有本机助手中的工作副本仍使用其原来的存储位置。与 Android 同步 API 密钥时选择 MDBX2 密码源。扩展沿用 Android 的原生 api-token 对象 UUID、载荷结构和标签，保留未知字段、稳定的自定义字段 ID、备注与收藏。扩展的归档状态放在 Android 可保留的附加标签字段中；Android 当前不显示这一归档标记。普通 WebDAV JSON 备份、Bitwarden 和 KeePass 不提供此原生类型的无损映射，因此不作为 API 密钥的保存目标。

### 与 Monica 安卓版进行 Wi-Fi 同步

管理页“设置与备份 → Wi-Fi 同步”通过同一 Wi-Fi 与 Monica 安卓版点对点加密同步本地库内容，不经过云端，也不发送主密码。

1. Windows 首次使用点按“配置本机通信组件”，下载并解压组件，按页面提供的命令配置当前扩展 ID。浏览器需要该组件建立局域网连接；MDBX 数据库引擎已内置。
2. 电脑与手机连接同一个 Wi-Fi，关闭 VPN；访客网络或开启 AP 隔离的路由器会阻止设备互连。
3. 配对：点按“显示本机邀请”，在手机 Monica 的附近设备同步中选择“添加设备”并扫码；也可以把手机生成的 `monica-lan:2:` 配对链接粘贴到页面中。
4. 同步：在 Android 的附近设备同步设置中务必选择“双向同步”；在浏览器设备列表中点按“同步”，同时在手机上点按“立即同步”，保持两端同步页面打开。配对不代表已同步；双方确认保存后才更新同步时间并弹出结果。弹窗显示本机实际保存／删除的项目和数量，对方接收显示确认状态。浏览器的“页面打开时自动同步”按所选间隔重试；目前尚未发布 mDNS 在线广播，不能保证唤起 Android 自动同步。

扩展遵循 Android 的连接规则：设备 ID 较大的一方监听，较小的一方通过局域网发现并主动连接。新建的浏览器身份会主动连接手机，因此通常只需要出站连接，无需为本机助手开放入站防火墙。页面会针对缺少本机助手、找不到手机、防火墙或网络隔离、配对链接无效等情况给出具体处理建议。Bitwarden 与 KeePass 来源不参与 Wi-Fi 同步。

新版通信组件与 Android 1.0.324 可在已配对连接中协商增量记录、缺失附件和加密断点续传；旧端继续使用完整加密传输。重连会重新认证，并核对原始密文及已接收前缀。接收历史删除时可审阅并选择跳过，双方实际保存完成后才确认成功。缓存只保存密文，取消、锁定和离开同步页面会撤销本次操作。Android 的 `monica-hotspot:1:` 热点邀请也可粘贴到页面：先按提示在系统 Wi-Fi 设置中连接热点，再连接设备；浏览器不会自动创建或加入热点。热点凭据只在当前页面临时显示，三分钟后清除。

### 常用账号免解锁填写

在管理页编辑一个有密码和匹配网站的普通登录项，勾选“允许免解锁填写”并保存。锁定后打开对应网站，Popup 会列出可免解锁填写的匹配账号；点击后只填写用户名和密码。TOTP、Passkey、复制密码、查看详情和修改设置仍需解锁。

开启后，任何能够使用当前浏览器配置的人都能点击填写这些账号。扩展使用独立、不可导出的设备密钥保存所选账号的加密副本，因而这部分账号依赖浏览器配置和操作系统保护；它们不再具有主密码锁定时的同等保护。关闭标记、删除或归档账号会撤销权限。这个标记只在当前扩展中生效，不写入 Android、KeePass 或 Bitwarden 的记录；恢复整库备份后需要重新勾选。

## WebDAV 使用

1. 在管理页打开“密码源”，填写 WebDAV 根地址、用户名和密码。
2. Android 使用加密备份时，同时填写相同的备份加密密码。
3. 先“测试连接”，再“加密保存”，最后执行“立即同步”。
4. 新建登录项时可选择该 WebDAV 源；开启自动同步时，保存后会安排写入新的 Android 兼容快照。

同步不会修改旧备份文件，而是在 `Monica_Backups` 中生成新的时间戳快照。两端需连接同一个远端位置，并在写入后由另一端同步／恢复对应快照；浏览器本地库本身不会自动变成 Android 数据库。并发编辑保留冲突处理流程。

“设置与备份 → 自动同步”默认开启。WebDAV 在管理页或 Popup 可见时每 15 秒检查一次，后台约每分钟检查；锁库后暂停。普通 Android 备份仍需手机先生成快照，且 Android 当前改动备份默认有 2 分钟静默期和 15 分钟最小间隔，插件无法提前接收尚未上传的数据。需要经常跨端编辑时，优先使用 Bitwarden 或双方连接的同一个 MDBX2 增量源。KDBX 变化后仍需传输整个加密文件。详见[同步兼容说明](docs/SYNC_COMPATIBILITY.md)。

插件编辑登录项的独立验证器绑定时，会转换成 Android 的 `boundPasswordId`，新建、更换和解除后再次同步均保留结果。旧记录缺少插件绑定字段时保留 Android 现有关联；跨 WebDAV 数据库的绑定或一个验证器绑定多个登录项无法由 Android 反向字段完整表示，写入会明确报错，避免丢失关系。HOTP 计数器和未知字段继续保留。

仅包含 Android 设备保护密钥引用的 Passkey 仍只显示元数据；受支持的便携 PKCS#8 私钥仅在加密备份边界内导入和写回。KeePass 互操作验证覆盖 AES-256 与 ChaCha20，Twofish 当前明确不支持。详见 [0.1.33 验证记录](docs/verification/VALIDATION-0.1.33.md)。

## Bitwarden 使用

1. 在“密码源”点击“连接 Bitwarden”。
2. 选择 US/EU 官方地址，或填写自托管 Vault 根地址。
3. 输入邮箱和主密码；需要 2FA 时选择方式并继续验证。
4. 如需把网站新建的 Passkey 保存到 Bitwarden，请勾选“设为新项目的默认保存目标”；创建、编辑和删除后会自动同步，也可点击“立即同步”。零计数 Passkey 的日常使用仅记录本机次数，不上传 Cipher。
5. 主密码不会保存；Token、Vault Key 和 FIDO2 私钥只存在于 Monica 加密信封中。逐项开启免解锁填写时，所选账号另有设备密钥加密的填写副本。

当前版本会从同步资料中解密用户 RSA 私钥，并分别解包可访问组织的对称密钥；共享 Cipher 按组织/集合归属读取，更新时保留 `organizationId` 和 `collectionIds`。缺失或损坏的组织密钥只会跳过对应共享项并保留本地缓存，不会影响个人库。新建项目目前仍创建为个人 Cipher，集合成员管理继续由 Bitwarden 官方客户端负责。Bitwarden FIDO2 的 base64 PKCS#8 密钥可用于登录；零计数登录不上传 Cipher，历史非零计数遵循官方同步递增规则，并附带服务器版本检查。计数更新和单凭据删除保留父登录及其他 Passkey。没有可导出密钥的引用只显示元数据。

如果网站已保存旧凭据的非零签名计数，改用 0 无法重置网站端记录；仍被拒绝的旧凭据可能需要在该网站重新注册。更新扩展后也要刷新登录网页，以载入新的 Passkey 脚本。

三种来源的区别、Android 当前实现差异和测试范围见 [Passkey 跨客户端策略](docs/PASSKEY_COMPATIBILITY.md)。

构建产物位于 `dist/`，可安装 ZIP 与每次重新生成的 `release/monica-extension-unpacked/` 位于 `release/`。

## 本地安装

1. 打开 `chrome://extensions` 或 `edge://extensions`。
2. 开启“开发者模式”。
3. 选择“加载已解压的扩展程序”。
4. 选择本项目的 `dist` 目录。
5. 打开扩展的“选项”页面并创建主密码。

也可以加载 `release/monica-extension-unpacked/`，其内容由 `npm run package:release` 完整替换，并与 `release/monica-extension-<version>.zip` 字节一致。ZIP 的根目录直接包含 `manifest.json`。

官方扩展包在 `manifest.json` 中包含固定的公开 `key`，相同 key 的扩展 ID 不因目录位置改变。缺少或改动 key 的自定义包可能使用不同 ID，从而读取另一份本地数据。浏览器配置文件也必须保持一致；卸载扩展或清除其数据会影响原有存储。

### 更新已解压的扩展

1. 在“设置与备份 → 检查更新”中检查 GitHub 正式发布。有更高版本且附件有效时，可直接点击“下载扩展 ZIP”；也可打开发布页查看说明。
2. 将 ZIP 解压到临时目录，找到直接包含 `manifest.json` 的文件夹。通过“打开扩展管理页”核对当前加载的原目录。
3. 将新版内容完整覆盖到该原目录，不要额外套一层文件夹。保留扩展安装及当前浏览器配置，不要先卸载或清除数据。
4. 保存未完成的编辑，点击“已覆盖，重新加载扩展”并确认，或使用浏览器扩展管理页的重新加载按钮。覆盖磁盘文件本身不保证已运行的后台切换到新版。
5. 再次打开 Monica，用原主密码解锁，并核对版本、构建标识和扩展 ID。重新加载会结束解锁会话，但不会主动删除保险库或退出 Bitwarden；服务端凭据过期等情况仍可能需要重新认证。

此流程提供下载和安装指引，扩展不会自动覆盖本机目录。相同版本号的开发构建可能与正式包不同，更新页只为更高正式版本提供直接 ZIP 下载，避免误装较旧代码。发布脚本仍支持 `--unpacked-dir <原目录>`，用于同步刷新已经安装的旧目录。

## 安全边界

- 密码、Token、Provider 凭据和 Passkey 私钥不得持久化为明文。
- Content Script 不提供读取密码库的消息接口。
- 自动填充要求用户在 Popup 或页面选择器中明确操作。
- 当前 JSON 导出是用户主动触发的明文导出，必须保存在可信位置。
- 加密整库备份保留原 AES-GCM 信封；替换现有库前同时验证备份主密码和当前主密码。
- Android WebDAV 的设备绑定 Passkey 只有密钥别名，浏览器中保持只读元数据，不能签名。
- Bitwarden 组织密钥无法解包时，相关共享 Cipher 会保持本地缓存并给出警告，不会以空结果覆盖。

详见 [架构说明](docs/ARCHITECTURE.md)。
