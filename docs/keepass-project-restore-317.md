# KeePass whole-project restoration

The trash list now offers whole-project restoration for an explicitly grouped KeePass password project. The confirmation shows its source, account groups and password count. It explicitly includes earlier-deleted members of that project: KDBX last modification times do not identify a reliable deletion cohort. MDBX retains its separate same-deletion-cohort semantics. Same-title independent entries and other databases are excluded.

The restore request captures the complete current project, including active and archived members. Before any encrypted write, the service checks exact membership/revisions, the full set of deleted members, native identities, supported credential metadata, shared account/OTP consistency and outstanding project conflicts. Active members remain unchanged. Inconsistent old members are retained in the trash and restoration is refused. The existing list offers the action for 2–50 trashed members; the complete KeePass project must have at most 100 members to fit a remote sync transaction.

All selected tombstones are restored and their provider mutations queued in one encrypted commit with a bounded local receipt. An identical request can be retried after response loss or restart without reapplying it over later edits/deletions. A different request cannot reuse its operation ID. Failed persistence retains every original tombstone and mutation. Completed staging is reported as a local restoration queued for sync, not a claim that the cloud file was updated. The existing source queue and KeePass durable publication/conflict protection handle synchronization.

The original native entries are restored, preserving their identity and native data. No new Android metadata carrier was added. Browser-created request receipts remain local encrypted bookkeeping. Android product sources remain untouched.
