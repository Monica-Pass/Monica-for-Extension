# 官方Bitwarden对照与第二批扩展优化（2026-11-12）

目标是改善查找、填写和大库响应。当前证据不足以声称Monica在所有场景优于官方Bitwarden；本轮量化的是Monica优化前后的差异。

## 对照基线

官方稳定版[2026.10.2](https://github.com/bitwarden/clients/releases/tag/browser-v2026.10.2)发布于2026-11-02，源码固定为`a540dcdb74db44fd90d20d721ef91a7225d5a34f`。官方`dist-edge-2026.10.2.zip`为26,131,130字节，SHA256 `f688b7c9880323803a71b8db66cc68db463549c178a7da4446779411660d2102`，与GitHub资产digest一致。

在隔离Edge配置中实际查看了官方默认密码管理器提示、欢迎页和登录页，3张截图已检查。选择跳过默认管理器设置，没有登录真实账号或改变日常浏览器。登录后的列表、搜索、缓存和填写策略来自固定源码审查；尚未运行官方与Monica同库、同服务器的端到端测速。

Monica基线是第一批优化后的1.0.104，构建`093891aacff9a23be99e`。本批仍未升版、提交、推送或发布。重型验证沿用BelowNormal、两个逻辑CPU、单worker和串行执行；只修改扩展目录，没有操作Android工程、ADB、模拟器、Gradle或既有进程。

## 优缺点与取舍

| 维度 | 官方可借鉴之处及限制 | Monica现状与本批处理 |
| --- | --- | --- |
| 查找条目 | 普通搜索拆词、跨字段匹配，也支持备注及至少8字符的ID前缀；100ms防抖，CJK支持单字符。高级Lunr按需建索引，普通搜索仍遍历候选。 | 原弹窗要求连续子串并接收全库摘要。本批支持跨标题、账号、网站、公开凭据标签的多词匹配、重音归一化及单字符；合并同一事件循环中的输入变化，不增加固定等待，每次最多返回20条。不搜索密码、备注、密钥或隐藏字段，搜索范围尚不等同官方。 |
| 大库列表 | 新版表格具有虚拟滚动和稳定行ID，但受功能开关控制，不能假设所有用户均已启用。虚拟渲染不等于没有全库数据处理。 | 第一批限制页码组件，本批在后台筛选/分页后才复制摘要，保留任意页跳转。当前网站匹配、Passkey/卡包及管理页仍有全量路径。 |
| 数据复用 | CipherService按用户共享解密数据源，列表与完整视图复用结果，有明确清理入口。 | 复用既有会话/信封绑定的解密缓存；新查询不另存明文索引。完整信封存储及未变化同步的整库成本仍待改进。 |
| 高频操作 | 自动填充、收藏、全部条目分区，搜索时合并结果；行操作区分填写、查看和打开网站。 | 保留当前站点优先、直接填写、复制与任意页访问。查询可以找到条目，不代表已获填写授权；后台仍检查origin、document与会话。跨次打开保留位置、完整键盘流程仍需专项比较。 |
| 产品定位 | 官方以Bitwarden账号、组织和跨设备体验为中心，也支持自托管；实际登录页具有通行密钥和SSO入口。完整组织交互本轮未实测。 | Monica适合需要本地、KeePass、MDBX、WebDAV与Bitwarden并存的用户，但来源与设置增加了复杂度。不能只靠增加功能来弥补等待；本批未新增SSO/组织能力。 |
| 加载成本 | 响应式共享状态、列表视图和按需索引值得借鉴；框架或ZIP体积本身不能证明速度。 | 通用条目编辑器、MDBX源管理、附件管理、KeePass历史4个模块改为本地按需加载，沿用原有条件挂载和关闭/锁定规则。 |

本批独立实现上述思路，没有复制官方源码。保持Monica既有M3E外观和分页交互，没有降低KDF、取消认证或延迟关键恢复回执。

## 实现与安全边界

- `VAULT_LIST_LOGIN_SUMMARIES`增加有界查询参数；无参数时保留原数组响应。可信扩展页面且已解锁才能查询。页码必须为1至1,000,000的安全整数，文本最多1024字符、显示标签160字符、URL8192字符，每页固定20条。复用已有的最多100个匹配ID（每个最多512字符）排除当前站点条目；更大的匹配集合才回退URL匹配。输入ID数组单独复制。
- 查询在原安全读取队列和解密缓存中完成，只复制结果摘要。密码组公开序号先按完整活跃集合计算，再筛选分页，避免搜索后“密码2”变成“密码1”。返回对象独立，调用者修改不能污染缓存；归档/删除条目不参与。
- Popup按页请求，查询代、刷新代及解锁状态共同拒绝迟到结果。改词立即移除旧搜索结果，零延时定时器合并同步变化；当前站点候选继续优先。关键词每次请求只拆分一次，图标等完整摘要只为最终页构造。网站禁止自动填充时，其条目仍能在全部登录项中查找和复制，最终填写保护不变。
- 4个管理模块仅在原有开启条件成立时加载。锁定/关闭后迟到模块不能自行挂载或恢复操作；不新增网络权限或远程脚本。

## Monica同库性能对照

测量构建为`0ad5526d0ad8960c8b59`。同一台机器、Edge 157.0.4341.46、两个逻辑CPU、串行隔离配置，分别导入5,000条合成登录项，其中1条匹配当前网站，不含大附件、多密码组或大量站点匹配。性能探针使用headless Edge，20项交互回归使用有界面的Edge。基线为第一批结束后的构建，不是最初版本，也不是官方Bitwarden。未使用真实用户库或远端服务器。

| 指标 | 第一批结束后 | 本批测量构建 | 解释 |
| --- | ---: | ---: | --- |
| 初次全部登录项响应行数 | 5,000 | 20 | 全库仍可搜索及跳页 |
| 同一响应JSON字符数 | 922,802 | 3,752 | 减少99.59%；字符数不等于堆内存 |
| 管理页首次请求的本地资源文件总字节 | 2,879,799 | 2,668,721 | 减少7.33%；不等于网络压缩流量 |
| 弹窗导航至20条回退结果显示 | 678.4ms | 592.2ms | 各1次，含驱动等待，不是P50/P95 |
| 暖刷新3次中位数 | 289.2ms | 211.2ms | 全刷新测量，受机器负载影响 |
| 前台搜索至DOM更新后下一动画帧 | 11.8 / 9.0 / 5.8ms | 38.8 / 29.0 / 22.8ms | 3个不同单结果查询；后台分页多一次消息往返 |

搜索结果如实保留取舍：原版已将全库预装到弹窗，单次本地搜索更快；新版减少开窗传输和复制、支持跨字段多词，但本次单次搜索约多20ms。不能据此宣称所有交互都加速。没有另加明文索引或长期缓存来换取这20ms。

探针迭代证据全部保留：最早100ms固定等待时驱动计时约81→283ms；50ms版本约121→221ms。最终移除固定等待。随后页面内动画帧计时出现约0.7–1秒，检查发现站点仍是活动标签页；该轮`final02`保留但不作为前台交互结果。`final03`在目标发现完成后显式将弹窗置前并断言`visibilityState=visible`，使用MutationObserver及下一动画帧计时。不同探针口径之间不直接比较。三次查询不足以生成可靠的P95；单次堆和DOM计数波动很大，不声称内存或泄漏改善。

## 后续优先级

1. 将当前站点匹配、Passkey/卡包及管理页进一步改为有界摘要，并验证锁定/切源下的稳定位置恢复。
2. 改进Bitwarden本地增量和无变化检查，避免网络已增量、本地仍整库复制；批次CryptoKey复用需要单独测量及撤销测试。
3. 用同一个合成自托管数据集和典型网页测官方与Monica的P50/P95、查找→填写操作步数、分步登录和注册保存成功率。本轮不能替代此项验收。
4. 逐记录加密存储与迁移恢复独立设计，保留写队列、原数据及崩溃恢复回执。
