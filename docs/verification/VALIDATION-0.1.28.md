# 0.1.28 更新后解锁修复与验证记录

日期：2026-09-11。本地开发包，保留原有未提交改动。

## 问题与复现

用户反馈：0.1.27 的完整管理页输入解锁密码后，显示“不支持的 Monica 运行时命令。”。

在隔离浏览器中，保持 0.1.23 后台运行并覆盖为新版页面文件，复现了相同提示。请求记录显示 `VAULT_UNLOCK` 成功，随后 `VAULT_LOCKED_AUTOFILL_IDS` 被旧后台拒绝。管理页把后续数据加载错误显示在解锁表单中，因此出现后台已经解锁、界面仍停在登录页的状态。完整加载同一版本的对照组可以正常解锁。

这确认了一个可复现的更新兼容性问题；仅查看扩展管理页显示的版本号不足以判断驻留后台是否包含新版命令。

## 修复

- 页面首次发送运行时请求前，先读取 `RUNTIME_INFO`，比较 UI 与后台代码中各自编译的版本和协议号。
- 创建密码库、主密码解锁和 Windows Hello 解锁前再次检查；不向不兼容的后台发送解锁密码。
- 同时发生的界面读取共用一次检查，成功后复用结果；没有增加后台轮询或常驻计时器。
- 旧后台、不兼容的版本/协议以及已知命令被拒绝时，返回可识别的重载状态。管理页清理视图并隐藏认证输入；Popup 清空输入的主密码。两个入口均提供“重新加载扩展”按钮。
- 重载沿用原扩展身份及加密 IndexedDB。浏览器会关闭旧扩展页面，重新打开 Monica 后继续使用原密码。界面提示用户先保存其他 Monica 窗口中的修改。
- 新提示支持八种语言；切换语言时立即更新。运行时分发增加 TypeScript 穷尽检查，新增命令遗漏处理分支会导致类型检查失败。

没有修改密码库加密格式、KDF 参数、逐项免解锁授权规则或同步协议。

## 安装与恢复

- ZIP：`release/monica-extension-0.1.28.zip`，1,862,301 字节。
- SHA-256：`ddc6e2ce169e519e61cea4a0218d42f0e25b866bab832f2feef306c01465f4d9`。
- 可加载目录：`release/monica-extension-unpacked`；开发构建：`dist`。

已安装用户应完整更新到原加载目录，然后在 Chrome/Edge 的扩展管理页点击 Monica 的“重新加载”，关闭旧管理页并重新打开 Monica。沿用原目录可以保持开发者模式扩展 ID 与已有本地数据。若本来加载的是本项目的 `dist`，该目录已包含本轮修复，重新加载后即可使用。

打包使用 `node scripts/package-release.mjs --allow-dirty`，并以 `node scripts/verify-release.mjs --allow-dirty` 校验。这是本地开发交付，没有提交或发布到远端。
