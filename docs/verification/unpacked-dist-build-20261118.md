# 本地 dist 构建与 Edge 注册保留（2026-11-18）

验证包为 1.0.104，构建标识 `7b88dbbca4599c0646d1`，沿用 Sengoku Nadeko 代号。已修复标准构建先清空已加载目录的风险；尚未复现用户日常 Chrome 中“扩展管理页完全消失、需要重新加载已解压扩展”的原始症状，不能把该风险认定为唯一原因。

## 已确认的风险与改动

旧命令在 Vite 编译后才生成后台、content/MAIN-world 脚本和内置浏览器引擎。真实 Vite 的小型目录实验确认：编译结束后 manifest 已复制回来，但原有 background.js 已被删除。因此浏览器在这一阶段读取 dist 会遇到不完整的扩展。此实验确认文件可用性风险，没有证明浏览器一定会删除安装注册。

标准 `npm run build` 现在在 `.tmp/extension-build-*` 编译全部产物，沿用 TypeScript、图标字体、固定来源浏览器引擎和四页面资源校验。成功后预备完整替换文件和原文件备份，逐文件 rename 更新原 dist，依赖先于 HTML、manifest 最后，最后清理过期文件。失败编译不触碰旧包；发布失败尝试回滚，回滚失败保留恢复副本并明确报错。并发构建拒绝，已声明资源缺失、目录穿越或符号链接在发布前拒绝。

这不是跨文件事务或断电恢复保证。构建和普通页面刷新不会保证磁盘上的新脚本立即替换浏览器缓存的旧 service worker；更新后仍应使用扩展的“重新加载扩展”入口。密码库、加密、权限和浏览器配置的生产逻辑没有改变。直接执行 vite 或 worker 子脚本不经过暂存发布流程，维护者应使用标准命令，细节见 [发布流程](../RELEASE.md)。

最终冻结源码重复构建期间，每轮读取 manifest、后台、两个网页脚本和四个 HTML，manifest 同时解析 JSON。23,926 轮采样没有缺失、空文件或无法解析的 manifest。构建期间启动 Edge，随后完成两次普通重启，注册保持 ENABLED，路径和扩展 ID 保持一致；加密信封指纹和解锁后的合成条目不变。最终运行前后构建标识相同，这个结果证明重复构建与普通重启保留，不能独自证明旧后台升级。

独立的四项 Edge E2E全部通过：设置更新检查/失败/窄屏，真实 MDBX 引擎记录、密钥和附件持久化，以及管理页和 Popup 从旧后台重新加载后保留密码库。旧后台升级覆盖来自这两项独立 E2E；它们使用启动参数加载测试副本，不能替代上述普通注册持久性验证。

## 排除的探针与限制

用户后续表示不确定消失是否发生在构建或更新后。只读复查时，Chrome 开发者模式开启，旧/现两个注册记录都仍指向存在的 dist；所读记录未提供禁用原因，系统和当前用户注册表也未发现 Chrome 策略键或 Edge 的扩展安装限制项。当时没有运行中的 Chrome 主进程可核对启动参数。这些是检查时的静态状态，不能证明消失时的状态，也不能排除浏览器内部注册、配置完整性或其他外部变化。未据此删除旧记录或认定两个 ID 就是原因。

早期 CDP 安装的扩展即使文件完整，普通重启也会消失；它带有不同安装标记，不能作为手动安装的复现。命令行首次加载后不再传参数也不持久化，同样排除。一次目录安装实际选到 dist，而缺文件实验操作副本，因此缺文件结果无效；后续加入路径断言后明确失败。修改自有隔离配置中的安装路径也未取得健康基线，未用来证明用户原因。自动审批拒绝 Edge 目录选择界面操作，后续有效验证复用已手动安装的隔离配置。

合成数据探针最初使用了错误的项目字段和状态结构，各失败一次；修正为生产模型和状态枚举，没有放宽导入校验。旧后台 reload 后立即访问的短暂 ERR_BLOCKED_BY_CLIENT 也保留为探针失败；等待扩展就绪是既有升级测试的要求，不是此次生产修复。

只测试 Edge 和自有合成库，未在日常 Chrome 复现移除注册，未修改其偏好文件、删除旧 ID 或操作用户库；未测试 Firefox、断电、杀进程中途发布或全部文件锁场景。原始探针、配置、日志、JSON 和开发包只留本地 `.codex-tasks/20261118-dist-disappearing/`。保留其他工作区改动；未提交、推送、升版或发布。
