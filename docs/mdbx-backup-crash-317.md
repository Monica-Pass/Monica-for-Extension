# Complete-backup crash recovery (1.0.317 work)

New Native Host exports use an OS file lease in an explicitly named temporary directory. Startup removes an abandoned leased directory only after acquiring its lock. Another Host's active export survives startup and remains downloadable. Download file handles close before directory cleanup on orderly shutdown, release, expiry or vault lock. There is no change to vault encryption, credentials or the portable archive layout.

The scavenger accepts only `complete-backup-v1-` plus the generated 16-character suffix and a regular `.owner.lock`. A separate file lock serializes directory creation with cleanup. Directory roots and descendants containing symlinks or Windows reparse points are preserved. `imports`, `vaults`, persistent `backups`, unleased older layouts and user files are outside its scan. OS locks avoid PID-reuse and age-based deletion hazards. The added `fs2` dependency is pinned to 0.4.3 in the Host manifest and lockfile.

## Android boundary

The current Android ordinary document picker passes only a single file URI. The ViewModel copies it without a parent-tree grant, and stores `externalTreeUri = null`; the external-storage service copies sidecars only with that grant. Merely extracting the ZIP next to `.blobs` therefore does not establish full attachment restoration through this screen. The source trace is recorded separately in `raw/backup-crash-android-source-trace.json`. No current Android runtime result is claimed: its sources, generated bindings and native libraries are being changed by another task, and this task did not build, install or modify them, or use its running emulator.

Removed the unsupported Android extraction instruction from the extension, seven translation catalogs and [editable local Canvas](design/complete-backup-317.md). The actual Edge hint and Canvas render were inspected. Full Android SAF/archive acceptance, prior Android Passkey defects, OneDrive account login, remote backend coverage, restore-staging cleanup and release packaging remain open. Legacy unleased export directories are intentionally not scavenged automatically.
