# 0.1.38 Passkey 登录与跨客户端使用修复

> 本地开发阶段记录：文中的版本号未作为 GitHub Release 发布，相关改动已汇总到[正式版 0.1.37](RELEASE-0.1.37.md)。

后续更正：0.1.39 对 Bitwarden 的历史非零计数恢复官方同步递增规则，替代本版本的统一归零策略；详见 [0.1.39](RELEASE-0.1.39.md)。

修复 Android/KeePass Passkey 被误识别为普通登录项，以及 GitHub 等要求用户验证的网站在未配置 Windows Hello 时直接转到系统验证器的问题。

- 无密码但带用户名、网址或备注的有效 KeePass Passkey 可正常参与网站登录；保留私钥、凭据 ID、原始密钥引用及未知字段。
- 主密码保护的密码库通过独立 Monica 窗口确认身份。主密码不进入网站或内容脚本，验证仅授权当前请求；取消、锁定、页面跳转或凭据变更会停止操作。
- 修复网页过早发起请求时内容脚本尚未就绪的问题，避免丢失首次请求或重复注册。
- 注册和登录的签名计数始终为 0，使用次数单独记录。保存一致的备份标志并保留明确导入的标志，避免副本各自自增或标志变化影响跨端登录。

更新后，在扩展管理页重新加载原来的 Monica，再刷新需要登录的网站。使用相同的解压目录加载，浏览器中已有的密码库继续保留。

如果网站已经记录旧凭据的非零签名计数，插件无法重置网站端状态；仍被拒绝的旧凭据可能需要在该网站重新注册。Android 设备绑定密钥引用无法转换为可导出私钥；浏览器当前签名支持 ES256，条件式自动填充及不支持的验证器请求仍交由浏览器处理。

验证过程使用虚构记录与隔离浏览器配置；本地包只含程序、资源、许可证和构建说明。详见 [验证记录](VALIDATION-0.1.38.md)。
